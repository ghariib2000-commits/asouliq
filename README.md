# ASOUL.IQ

بوت Telegram مالي لمتابعة الأسواق والأصول في مصر.

## الهيكل

```
bot.py                     نقطة التشغيل (متوافقة مع Procfile)
app/config.py              الإعدادات من متغيرات البيئة
app/clock.py               توقيت القاهرة
app/db/connection.py       اتصال SQLite (WAL + Foreign Keys)
app/db/migrations.py       ترحيلات مُصدَّرة بإصدارات
app/providers/             مزودو البيانات (واجهة موحدة)
app/services/market.py     محرك الأسعار + تخزين مؤقت + صياغة الرسائل
app/services/users.py      بيانات المستخدمين وتفضيلاتهم
app/bot/handlers.py        أزرار وقوائم Telegram
legacy/                    الكود القديم للمراجعة فقط (غير مستخدم)
tests/                     اختبارات
```

## أوامر البوت

| الأمر | الوظيفة |
|---|---|
| `/start` | الموافقة على الشروط والقائمة الرئيسية |
| `/search <اسم أو كود>` | البحث في سجل الأصول (مثال `/search دولار`) |
| `/watchlist` | قائمة المتابعة الشخصية مع أحدث الأسعار |
| `/alerts` | عرض تنبيهاتي وحذف أي واحد |
| `/alert <كود> <نوع> <قيمة>` | إنشاء تنبيه (above/below/up/down أو فوق/تحت/ارتفاع/انخفاض) |
| `/backup` | نسخة احتياطية من القاعدة (للمالك فقط) |

## محرك التنبيهات

- يعمل كـTask داخل نفس عملية البوت كل `ALERT_INTERVAL_SECONDS` (افتراضيًا 300 ثانية)،
  فلا يوجد Polling ثانٍ ولا Conflict.
- يجلب سعر كل أصل عليه تنبيه **مرة واحدة** لكل مزود، لا مرة لكل مستخدم.
- لا ينبّه على سعر قديم (أقدم من `PRICE_STALE_MINUTES`).
- يمنع التكرار عبر `last_triggered_at` + `ALERT_COOLDOWN_MINUTES` (افتراضيًا 60 دقيقة).
- كل إرسال يُسجّل في `notification_log` بحالة `sent` أو `failed` مع السبب.
- فشل الإرسال لا يحجب المحاولة التالية؛ فشل المصدر لا يوقف البوت.

## سجل الأصول

`app/catalog.py` هو المصدر الوحيد لتعريفات الأصول: **18 عملة** مقابل الجنيه
(مع مراعاة وحدة التسعير لكل 100 للين الياباني) و**4 أصناف ذهب**.
إضافة أصل جديد = سطر في الملف ثم إعادة تشغيل البوت (مزامنة idempotent).

## قواعد حماية البيانات

- لا تُرفع قاعدة البيانات أو `.env` إلى GitHub (`.gitignore` يمنع ذلك).
- كل تغيير في المخطط يمر عبر `app/db/migrations.py` بإصدار جديد.
- لا نستخدم `DROP TABLE` أو `DROP COLUMN`، ولا نُعيد إنشاء القاعدة.
- الترحيل يعمل تلقائيًا عند بدء التشغيل ويحافظ على المستخدمين الحاليين.

## Railway: تخزين دائم (إلزامي)

بدون Volume يُمسح نظام الملفات مع كل Deploy أو Restart، ويفقد البوت كل المستخدمين.

1. Service → Settings → Volumes → **New Volume**.
2. Mount path: `/data`.
3. Variables → `DATABASE_PATH=/data/asouliq.db`.
4. Variables → `OWNER_TELEGRAM_ID=<معرّفك في Telegram>` لتفعيل `/backup`.
5. Redeploy واتأكد إن السجل لا يطبع تحذير "قاعدة البيانات داخل مجلد المشروع".

### نسخة احتياطية من قاعدة الإنتاج

- من داخل البوت: أرسل `/backup` من حساب المالك — يصل الملف كوثيقة Telegram.
- من الخادم: `python -m app.cli backup`

## حالة المصادر

- **الذهب:** بيانات حقيقية من `api.gold-api.com` و `open.er-api.com`،
  والسعر **تقديري محسوب** ويُذكر ذلك في الرسالة.
  تنبيه مهم: سعر الأونصة يتحدّث لحظيًا، أما سعر الدولار من هذا المصدر
  فيتحدّث **مرة واحدة يوميًا**، ولذلك يُعرض تاريخ تحديثه في الرسالة.
- **العملات الـ18:** من `open.er-api.com` (تحديث يومي)، وتُحفظ في `latest_prices`.
- **البورصة المصرية:** أسهم EGX + مؤشرات EGX30/70/100 من
  `scanner.tradingview.com` (مصدر سوق مجاني عام، بدون مفتاح).
  نحو 297 سهمًا تُسجَّل تلقائيًا في `assets` عند أول جلب، وأسماؤها إنجليزية
  لأن المصدر المجاني لا يوفر أسماء عربية (الترجمة تحتاج مصدرًا مرخصًا).

> ⚠️ **تنبيه ترخيص:** بيانات EGX من هذا المصدر العام **غير مرخّصة لإعادة
> التوزيع التجاري**. مناسبة للاستخدام الشخصي والتجريبي. قبل تحويل المشروع
> إلى منتج مدفوع أو بجمهور واسع، يجب الاتفاق مع مصدر مرخّص (EGID الرسمي
> أو EODHD). عندها يكفي تغيير `app/providers/egx.py` — واجهة المزود ثابتة.

لا تُعرض أي أرقام عند فشل أي مصدر — لا قيم افتراضية ولا تقديرات.

السعر المخزَّن يُعتبر قديمًا بعد `PRICE_STALE_MINUTES` (افتراضيًا 30 دقيقة)
ويُعرض بعلامة ⚠️ في قائمة المتابعة.
